# Control Plane: что сделать для релиза **0.2.3**

Короткий чеклист после того, как в GitHub прошёл **Publish Registry Release** для **`v0.2.3`** (или вы вручную залили тот же JSON манифеста).

## 1. Хранить полный JSON манифеста

В теле **`POST /api/ci/releases/register`** теперь приходит объект **`composeFileUrls`**: для каждого имени из **`composeFiles`** — строка с **`https://raw.githubusercontent.com/...`**.

**Сделайте в CP:** сохраняйте манифест как **JSON целиком** (или отдельное поле под произвольный JSON / `composeFileUrls`), без выкидывания неизвестных ключей при сохранении в БД.

## 2. Отдавать клиенту тот же JSON

Эндпоинт, с которого install bundle качает манифест (или из которого вы копируете JSON в `deployment-manifest.json` на сервере), должен возвращать **`composeFileUrls`** так же, как пришло из CI.

**Проверка:** откройте манифест версии **`0.2.3`** в админке или через API — должны быть и **`composeFiles`**, и **`composeFileUrls`** с теми же ключами.

## 3. Старые релизы (0.2.2 и ниже)

У них **`composeFileUrls` не было**. Варианты:

- перевести установки на **`0.2.3`** и обновить манифест с CI; или  
- один раз **PATCH** манифеста / ручная правка в CP, если добавите генерацию URL у себя.

## 4. Prisma / схема (если манифест нормализован в таблицы)

Если сейчас колонки только под старый набор полей — добавьте хранение **`composeFileUrls`** (например `Json` / `text` с полным фрагментом), иначе клиентский **`client-pull-agent`** снова не увидит URL.

---

На стороне сервера клиента после этого: **`MANIFEST_URL=…`** (или путь к сохранённому JSON) + **`./suprex/client-pull-agent.sh`** — см. **`docs/RELEASING.md`**.
