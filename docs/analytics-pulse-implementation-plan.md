# Модуль аналитики «Пульс бизнеса» — план (обновлённый)

Обновления: глоссарий метрик, разделение Lead Funnel / Order Pipeline, RBAC v1 (ADMIN/LEAD/MANAGER), убран gross margin из обязательных KPI v1, разделение flow vs snapshot метрик, суженный scope Inventory v1.

## Analytics Definitions / Metrics Glossary

Единый глоссарий определений для всех метрик модуля. Использовать в коде (комментарии/константы) и при необходимости вынести в UI (tooltip / отдельная страница «Метрики»).

### Общие термины

- **Период** — интервал дат dateFrom–dateTo для расчёта метрик.
- **Сравнение (compare)** — дополнительный период compareDateFrom–compareDateTo для сравнения с основным (например, предыдущий месяц).
- **Новый клиент** — контакт или компания, у которых первый заказ (или первая активность) попадает в выбранный период.
- **Повторный клиент** — клиент, у которого был хотя бы один заказ до периода и хотя бы один в периоде.
- **Активный клиент** — клиент с заказом или значимой активностью (звонок/визит/задача) в периоде.
- **Спящий клиент** — клиент без заказов и без значимой активности в течение N дней (параметр, например 90).
- **Клиент под риском** — эвристика: падение объёма/частоты заказов или долгая тишина по активности.

### Lead Funnel (лиды)

- **Лид** — запись в сущности Lead (входящая заявка/обращение).
- **Воронка лидов** — подсчёт лидов по статусам LeadStatus (NEW, IN_PROGRESS, WON, LOST, NOT_TARGET, SPAM) на дату или за период.
- **Конверсия лидов** — доля лидов со статусом WON от всех лидов (в периоде или на срезе).
- **Причина потери лида** — поле Lead.statusReason при статусах LOST / NOT_TARGET / SPAM.
- **Время до первого ответа по лиду** — разница между Lead.createdAt и временем первого связанного звонка (Call по leadId) или первой исходящей активности.

### Order Pipeline (заказы)

- **Заказ** — запись Order. Статусы — OrderStatus (NEW … SUCCESS / CANCELED / RETURNING).
- **Воронка заказов (pipeline)** — подсчёт заказов по OrderStatus: по количеству и по сумме totalAmount (на дату или за период).
- **Конверсия заказа в оплату** — доля заказов, по которым есть оплата (paidAmount > 0 или Payment), от заказов в целевом статусе (например SUCCESS).
- **Среднее время в этапе заказа** — по OrderStatusHistory: разница между переходами fromStatus–toStatus (среднее по этапам).
- **Старение заказа в этапе** — время с момента последнего перехода в текущий статус до «сейчас» или до следующего перехода.
- **Причина отмены заказа** — OrderStatusHistory.reason при toStatus = CANCELED (или будущее поле Order.cancelReason).

### Финансы

- **Выручка (revenue)** — сумма Order.totalAmount по заказам в периоде (или по статусу). Не путать с оплаченной суммой.
- **Оплачено (paid)** — сумма Order.paidAmount или сумма Payment.amount (status = COMPLETED) за период paidAt.
- **Дебиторская задолженность (debt)** — сумма Order.debtAmount по заказам с debtAmount > 0.
- **Просроченная дебиторка** — подмножество debt: заказы с датой ожидаемой оплаты в прошлом (если есть поле) или эвристика по дате заказа + типичный срок.
- **Средние дни до оплаты** — разница между датой создания заказа (Order.createdAt) и датой первой/полной оплаты (Payment.paidAt).
- **Gross margin** — не входит в обязательные KPI v1 при отсутствии валидной себестоимости (см. раздел про маржу ниже).

### Продукты и остатки

- **Топ по выручке** — сумма OrderItem.lineTotal по productId за период.
- **Топ по количеству** — сумма OrderItem.qty по productId за период.
- **Товар без движения** — товар, по которому нет OrderItem в выбранном периоде.
- **Текущий остаток** — Product.stock на момент запроса (snapshot).
- **Low stock (v1)** — товары с остатком ниже порога (константа или настройка, если появится).
- **Out of stock (v1)** — товары с stock = 0.

## Lead Funnel vs Order Pipeline (явное разделение)

- **Lead Funnel** — жизненный цикл лида: от создания (Lead) до статуса WON / LOST / NOT_TARGET / SPAM. Метрики: количество и конверсия по LeadStatus, причины потерь (statusReason), время до первого ответа, разбивки по LeadSource, ownerId. Данные: Lead, LeadEvent, Call (по leadId).
- **Order Pipeline** — жизненный цикл заказа: от создания (Order) по этапам OrderStatus до SUCCESS / CANCELED / RETURNING. Метрики: количество и сумма по этапам, конверсия между этапами, среднее время в этапе, старение, разбивки по ownerId, orderSource, региону/типу клиента. Данные: Order, OrderStatusHistory, OrderItem, Payment.

Связь между ними: конвертированный лид (WON) может породить заказ; в v1 связь опционально хранится через Lead.convertedOrderId. В отчётах и UI разделы «Лиды» и «Продажи (заказы)» должны быть явно разделены: отдельные вкладки/блоки и отдельные метрики (Lead Funnel / Order Pipeline).

## RBAC v1

- **ADMIN** — полный доступ: все отчёты, все менеджеры, все клиенты/заказы/лиды. Нет фильтрации по ownerId.
- **LEAD** — доступ по «команде»: те же отчёты, что и у ADMIN, данные по всем менеджерам (team). Реализация: не накладывать фильтр ownerId; при отсутствии сущности Team «team» = все пользователи с ролью MANAGER (и при необходимости LEAD).
- **MANAGER** — только свои данные: все метрики и списки фильтруются по ownerId / assigneeId = текущий пользователь (заказы, лиды, визиты, задачи, контакты/компании, где он owner).

Видимость раздела «Аналитика» в меню: ADMIN, LEAD, MANAGER (все три роли видят раздел; наполнение разное).

## Gross margin и KPI v1

В текущей схеме нет валидной себестоимости: в Product только basePrice, в OrderItem — price и lineTotal, без cost. Использование basePrice как proxy себестоимости может вводить в заблуждение.

**Gross margin исключён из обязательных KPI v1.** В Overview и Finance не показывать «валовая прибыль» и «margin %» как обязательные блоки. Допустимо в v1: выручка (revenue), оплаты (paid), дебиторка (debt), средний чек, количество заказов. После введения Product.costPrice или OrderItem.costSnapshot — добавить margin в глоссарий и в UI.

## Flow-based vs snapshot-based metrics

- **Flow-based (потоковые)** — метрики за период: считаются по событиям/фактам, у которых дата попадает в период (createdAt, paidAt, дата смены статуса и т.д.). Примеры: выручка за месяц (заказы с createdAt в месяце), оплаты за месяц (Payment.paidAt), новые лиды за период (Lead.createdAt), конверсия лидов в периоде.
- **Snapshot-based (срезовые)** — метрики на дату/момент: состояние на «сейчас» или на конец периода. Примеры: дебиторская задолженность на дату (сумма Order.debtAmount по незакрытым заказам), текущий остаток товара (Product.stock), количество заказов в статусе IN_WORK на конец периода, список просроченных задач на сегодня.

В реализации и в глоссарии явно помечать метрики как flow или snapshot; при compare для flow сравнивать два периода, для snapshot — при необходимости два среза на конец периодов.

## Inventory v1 — сужение до реально доступных данных

В схеме есть только **Product.stock** (текущий остаток). Нет: reserved, dead stock, минимальный порог, история движений.

**Inventory v1 включает только:**

- **Текущий остаток (current stock)** — Product.stock по каждому товару (snapshot).
- **Low stock** — товары с остатком ниже порога (порог — константа в коде или одна настройка, например 5).
- **Out of stock** — товары с stock = 0.

**Не входит в v1:** reserved stock, dead stock, shortage impact, aging inventory. Оставить на последующие итерации после появления нужных данных в схеме.

## Связь с основным планом

Остальная часть плана (аудит проекта, доступные модели, пробелы, план реализации, фазы, риски) сохраняется с учётом:

- В Overview/Finance не включать gross margin в обязательные KPI.
- В разделе «Продажи» явно разделять блоки: Lead Funnel (лиды по LeadStatus) и Order Pipeline (заказы по OrderStatus).
- В RBAC везде использовать правило: ADMIN full, LEAD team, MANAGER self only.
- В разделе Inventory v1 — только current stock, low stock (по порогу), out of stock.
- В документации/коде использовать глоссарий определений и разделение flow vs snapshot.
