# Структура мобильных экранов и сценарии

## Навигация (bottom tabs)

1. **Сегодня** — главный вход.
2. **Карта** — визиты дня на карте + текущее положение.
3. **Клиенты** — поиск и карточка.
4. **Задачи** — inbox на день.
5. **Ещё** — топливо за день, смена/GPS, офлайн-очередь, настройки, выход.

## Сценарии

### S1. Начало рабочего дня

Менеджер открывает **Сегодня** → «Начать смену» → `POST /field/shifts/start` с `plannedDistanceKm` (из маршрута) и `trackingEnabled`. Видит баннер «Локации собираются».

### S2. Поездка к клиенту

Карточка ближайшего визита: **Позвонить**, **Навигатор** (внешнее приложение), ETA (клиент может считать локально по Maps).

### S3. На месте → старт визита

«Начать визит» → запрос геолокации → `POST /visits/:id/start` с телом GPS → экран показывает человекочитаемый результат: «На месте» / «Подойдите ближе…» / «Слабый GPS».

### S4. Завершение визита

Исход встречи, заметка, опционально follow-up → «Завершить» → `POST /visits/:id/complete` с GPS-телом + поля результата (как сейчас в CRM).

### S5. Топливо

**Ещё → Топливо** загружает `GET /field/fuel/day?date=` — показывает план км, расчёт, статус. Кнопка «Обновить из смены» вызывает `POST /field/fuel/day/recalculate`.

### S6. Конец дня

«Завершить смену» → `POST /field/shifts/:id/end`. Баннер трекинга скрывается.

## Принципы UI (кратко)

- Одна главная кнопка действия на экране «Сегодня».
- Визит — пошаговый wizard, без длинных форм по умолчанию.
- Сообщения GPS — простым языком, без кодов ошибок.
