# MVP: объём, GPS, топливо, верификация

## Цель MVP

Дать менеджеру в поле **один главный экран «Сегодня»**, быстрый сценарий визита и **серверную фиксацию GPS** при старте и завершении визита, плюс **оценку топлива за день** по плановому километражу маршрута и профилю авто.

## Экраны MVP (mobile)

1. **Сегодня** — ближайший визит, список на день, CTA «Навигатор», прогресс, старт/завершение смены (field shift).
2. **Карта** — точки визитов на день (через существующие данные визитов/маршрута).
3. **Клиенты** — поиск, карточка контакта/компании (read-only + быстрые действия: позвонить, открыть визит).
4. **Визит** — пошагово: подготовка → старт (с GPS) → результат → завершение (с GPS).
5. **Задачи** — список своих задач на сегодня/просрочку, закрыть/перенести (минимум).
6. **Топливо (день)** — план км, профиль расхода, расчёт литров и суммы, статус черновика.

Не в MVP: полноценный каталог заказов с созданием заказа, документы, push, офлайн-sync (описаны в дорожной карте).

## Политика GPS (MVP)

| Режим | Поведение |
|-------|-----------|
| Смена **не активна** | Клиент **не** шлёт фоновые сэмплы; старт визита по-прежнему может отправить точку по кнопке. |
| Смена **активна**, `trackingEnabled: true` | Приложение шлёт батчи `POST /field/shifts/:id/samples` с интервалом 1–5 мин или по перемещению (реализация на клиенте). |
| Смена **активна**, `trackingEnabled: false` | Только точечные координаты при старт/комплит визита. |

Персональные данные: явная индикация «идёт сбор локаций», остановка смены одной кнопкой.

## Правила верификации визита (сервер)

На `POST /visits/:id/start` и `POST /visits/:id/complete` передаются опционально:

- `lat`, `lng` (WGS-84)
- `accuracyM` (горизонтальная точность, метры)
- `clientRecordedAt` (ISO-8601)
- `permissionState`, `locationProvider` (строки, для аудита)

Алгоритм (упрощённо):

1. Нет координат на клиенте → `NO_FIX`.
2. У визита нет плановых `lat`/`lng` → `MANUAL_REVIEW`.
3. `accuracyM` задан и **> 150 м** → `NO_FIX` (низкая точность; можно ослабить настройкой позже).
4. Иначе считается расстояние до точки визита (Haversine), сравнение с `radiusM` (по умолчанию 100 м):
   - `distance ≤ radiusM` → `VERIFIED`
   - `distance ≤ radiusM + 75` → `NEARBY_WARNING`
   - иначе → `OUTSIDE_RADIUS`

**Политика блокировки (MVP): мягкая** — визит стартует/завершается всегда, статус верификации сохраняется для отчётов и ручного разбора.

События пишутся в `VisitGpsEvent`; на `Visit` дублируются `startGpsVerification` / `completeGpsVerification` для быстрых списков.

## Топливо (MVP)

- Источник **плановых км**: при старте смены можно передать `plannedDistanceKm` (например, из ответа `RoutePlan` на клиенте).
- Формула: `plannedKm * (litersPer100km / 100) * pricePerLiter` — значения из `UserFieldProfile`.
- Сущность `FuelDayReport` на пользователя и календарный день: черновик, поля расчёта, статус компенсации.

Фактический км по GPS-треку — **v2** (агрегация по `FieldLocationSample`).
